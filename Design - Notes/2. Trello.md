If one user deletes a column while another is dragging a task into it, 
-we can’t rely on ‘last write wins’ because that can leave a task pointing to a deleted column.

-Instead, the server is the source of truth and uses versioning. When a user moves a task, the request includes the column’s version. If that column was deleted in the meantime, the server rejects the move and returns a fallback column like ‘Backlog’.

-The frontend controller then updates the store to move the task into that fallback column and shows a small notification to the user.”
